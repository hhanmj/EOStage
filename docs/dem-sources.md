# DEM 数据源、并发与恢复策略

EOStage 沿用统一 DEM 工作流，不增加第二套下载面板。每个 DEM 请求会冻结 Dataset、Provider、AOI/BBox、源/目标高程基准、输出目录、代理策略和转换策略，并以独立 `task_id` 进入同一个下载中心。

## 已实现的数据源

| Provider | Dataset | 认证 | 源高程基准 | 覆盖与恢复 |
| --- | --- | --- | --- | --- |
| Copernicus public AWS COG | `COP30` | 匿名 HTTPS | EGM2008 | 全球公共陆地区域；GLO-30 海洋位置可能没有瓦片；支持 `.part` 与 HTTP Range。 |
| Copernicus public AWS COG | `COP90` | 匿名 HTTPS | EGM2008 | 全球；支持 `.part` 与 HTTP Range。 |
| OpenTopography | `COP30`、`COP90` | API Key | EGM2008 | bbox API；不承诺字节级续传，失败时从零重启该请求。 |
| OpenTopography | `NASADEM`、`SRTM_GL1`、`SRTM_GL3` | API Key | EGM96 | 约 56°S–60°N 的陆地区域；不承诺字节级续传。 |
| OpenTopography | `AW3D30` | API Key | EGM96 | 约 82°S–82°N 的陆地区域；不承诺字节级续传。 |
| OpenTopography | `SRTM_GL1_ELLIPSOIDAL`、`AW3D30_ELLIPSOIDAL` | API Key | WGS84 椭球高 | 使用源数据原生椭球高语义。 |

`Auto` 只在当前 Dataset 已实现的 Provider 中选择。Copernicus 数据默认优先匿名 AWS 公共 COG；NASADEM 或 AW3D30 不会静默改成 COP30。选择了不支持该 Dataset 的 Provider 会明确失败。

## Copernicus AWS 的瓦片、拼接与裁剪

AWS 提供的是完整的 1° COG 瓦片，不会按 EOStage 的 AOI 在云端生成新 DEM。当前桌面原生路径下载所需瓦片后，在产品自带 Rust/GDAL 栅格边界内完成本地拼接和矩形裁剪：

1. 检查所有瓦片均为单波段、北向 `EPSG:4326`，并且 x/y 像元间距、原点相位、栅格类型、NoData 与像元语义一致；
2. 使用已经冻结的精确 DEM 请求 BBox 作为输出范围，不再额外扩边；
3. 在同一源像元网格上构建 VRT，并再次检查 VRT 没有改变源分辨率或网格相位；
4. 裁剪不指定输出尺寸或插值算法；如果相邻源瓦片网格不兼容则明确失败，不让 GDAL 取平均分辨率；
5. 跨日期变更线时，西/东两个已裁剪窗口必须具有相同的原生像元间距与行网格，软件按原宽度直接拼接；不同间距不会重采样到另一侧；
6. 输出完整性检查通过后才提升为正式结果。

因此，兼容源网格的拼接不会修改有效像元高程，也不会为了凑尺寸降低水平分辨率；遇到不同原生网格时会失败并要求显式科学处理，而不是静默插值。界面三位小数仍只是显示格式，不参与请求边界计算。源数据的 EGM2008 高程基准保持不变，只有用户另行选择高程基准转换时才执行对应转换。

## 并发模型

- DEM 任务并发默认 2，可在 DEM 下载目录区域配置 1–10，不放入全局设置页。
- 达到上限的新任务进入 FIFO 队列，不会覆盖或取消正在运行的任务。
- 暂停任务会释放任务槽，另一任务可以启动；继续时若没有空位则重新排队。
- 每个任务的暂停、继续、取消和重试只作用于自己的 `task_id`。
- 同一目标文件不能由两个任务同时写入。
- DEM 高程转换并发默认 1，与下载任务并发上限分开控制。
- Copernicus 单任务内部最多使用 4 个瓦片工作线程；这不是“最多 4 个 DEM 任务”。
- 多瓦片并行下载的界面进度按所有瓦片已完成字节聚合，不能在单块瓦片切换时回退。
- 排队任务只保存轻量计划和无凭据快照；下载线程、网络响应缓冲和瓦片工作池仅在任务取得运行槽后创建，不会按上限预先占用十份下载内存。

## 代理与速度

任务创建时冻结代理策略。显式代理只用于该任务；未配置时使用系统网络策略。公共源能减少账号门槛，但软件不能保证跨境网络、运营商或远端服务的实际带宽。不要把“不开代理速度慢”显示为下载失败。

同一 COP30/COP90 产品优先推荐公共 AWS COG：它可并行获取瓦片、支持 Range，并能复用本地瓦片缓存。OpenTopography 的全球 DEM API 是动态 bbox 栅格生成接口，服务端响应和跨境链路可能显著慢于 AWS；软件不能通过提高客户端并发把单个 OpenTopography 响应强行提速。可行措施只有选择 AWS、配置可靠的系统/显式代理、缩小 BBox，或避开远端高负载时段。

## 暂停、重启与完整性

Copernicus COG 瓦片下载使用 `.part`、Range、重试、GeoTIFF 魔数和大小检查，完成后原子替换。OpenTopography 当前没有可靠 Range 合同；中断后保留任务上下文，但再次执行远程请求时从零开始，界面不得声称字节级续传。

完成前的自检使用当前产品原生 GDAL 边界打开结果，检查尺寸、波段、CRS、仿射变换和 BBox 覆盖，并解码栅格。只有检查通过时才提升正式结果；已有文件也必须通过相应完整性检查后才能复用。

进度百分比只在服务器提供可信总字节数时显示。OpenTopography 若未返回 `Content-Length`，界面显示已接收字节、实时速度和“不确定进度”，不会伪造百分比；Copernicus AWS 在所有瓦片大小可确定后显示聚合百分比。

暂停和排队快照不含 API Key、代理凭据或认证 URL。应用重启后任务保持独立，必须由自己的任务控制恢复；一个任务失败不能改变另一个任务的状态。

## 高程基准

Dataset 的源高程基准与用户选择的目标基准分开记录。需要 EGM96/EGM2008 到 WGS84 椭球高转换时使用打包的 GDAL/rasterio、PROJ 与对应网格。不得仅修改文件名就宣称转换完成；缺少运行库或网格时必须给出明确错误和恢复建议。

## 验证重点

1. 连续创建多个不同输出目录的任务，确认最多运行数等于设置值，其余排队。
2. 暂停第一项，确认第二项可以启动；继续第一项不得突破并发上限。
3. 切换到 Copernicus AWS 时不要求 OpenTopography Key，任务仍记录真实 Provider。
4. 切换到 NASADEM/AW3D30 时确认不会被路由为 COP30。
5. 取消或断网后检查 `.part`、中文原因、重试行为和输出文件完整性。
