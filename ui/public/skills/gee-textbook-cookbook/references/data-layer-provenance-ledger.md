# 数据血缘台账与核验边界规范 (Data Layer Provenance)

一次严谨的遥感分析不止于“算出一张好看的图”，而在于**可追溯、可复验、语义不丢失**。每当涉及数据集选型、混合官方与社区库、缩放/掩膜换算或正式导出交付时，都应当保留一份紧凑的数据血缘记录（Data Layer Record），在 EOStage 预演卡和结果卡中作为可核查元数据随结果流转。

## 1. 血缘台账核心字段契约

| 字段 | 记录要求 |
| --- | --- |
| 目标物理量 (`target_variable`) | 明确测量或分类对象（如地表温度 °C、植被指数 NDVI、10 m 地类面积 km²） |
| 数据源性质 (`dataset_source`) | 官方目录 (`official`)、社区托管目录 (`community`)、用户私有资产或未登记来源 (`unknown`) |
| 资产编号 (`dataset_id`) | 精确到版本的 GEE 资产路径，以及是否已退役 (`deprecated`) 和推荐替代版 (`replacement_id`) |
| 时间范围与降维 (`time_range` / `temporal_reducer`) | 实际过滤区间（静态地形资产明确标注 `is_timeless: true`）与采用的合成算子（`median`/`mean`/`max`/`mode` 等） |
| 空间基准 (`spatial_extent_source` / `bbox`) | 明确来自绑定研究区（Working AOI）或显式传入外包框 |
| 尺度与投影 (`native_scale_m` / `analysis_scale_m` / `crs`) | 原生分辨率 vs 实际计算/导出分辨率（发生降采样或预览重采样时必须显式区分！） |
| 波段与定标 (`bands` / `scale_offset_note` / `unit`) | 参与运算的波段、乘除加减偏移及最终物理单位 |
| 质量掩膜 (`qa_mask_method`) | 明确写明所用掩膜方案（如 `Cloud Score+ cs>=0.60`、`QA_PIXEL Bits 0-5 + QA_RADSAT`、`None` 等） |
| 产物去向与核验状态 (`output_target` / `verification_status`) | 本机 GeoTIFF、外部批导出还是仅预览；标注目录已核验还是“社区待核验” |

## 2. 官方库与社区库的信任与核验红线

- **优先级**：同等功能与合适分辨率下，**优先选用 GEE 官方目录数据**；当社区目录提供官方暂无的特色产品时方可选用，并**必须在界面的来源标识与结果描述中醒目标注“社区目录”**。
- **目录条目 ≠ 最终科学契约**：社区目录检索卡片（甚至任何简洁目录摘要）只提供发现线索。正式写定量公式或导数前，必须以实际波段元数据与样例探针复核波段名、缩放因子、缺失值和许可条款；无法确认的项目一律保留 `未核验 / 待确认`，严禁凭空编造单位或缩放系数。
- **分辨率变更追踪**：若最初按原生全分辨率（如 10 m）发起确认，用户随后选择按预览分辨率（如 30 m）落盘，血缘记录**必须同步更新为实际产出的 30 m**，绝不可在最终产物卡片下方继续显示陈旧的 10 m 确认前参数。

## 3. 退役数据集与替代方案处理原则

- 默认检索自动排除已知退役产品（如旧版 `USGS/SRTMGL1_003` 在部分现代需求下优先推荐 `COPERNICUS/DEM/GLO30_2024_1`，旧 `MODIS/006/*` 升级为 `MODIS/061/*`，Landsat C1 升级为 C2 L2）。
- 当用户科研复现明确需要旧版资产时，方可返回历史条目并同时附带“已退役”标签与官方替代建议 ID，方便在新旧对照中说明潜在辐射/版本差异。

## 4. 未指定关键参数时的单轮澄清触发点

出现下列直接影响科学结论的缺项时，先提 1 个聚焦问题再动工：
1. 研究目标仅支持官方资产还是允许社区托管数据；
2. 降尺分辨率高于数据源原生尺度（强行超采无实际信息增益）；
3. 缺失时间合成方式或时间范围；
4. 去云掩膜对雪地/暗水体等特殊地物的取舍不明；
5. 产物形态模糊（要空间栅格、分区汇总表还是时序图表）。
