# GEE EECU 配额认知、默认上限与计算成本控制

GEE 运行以 **EECU（Earth Engine Compute Units，计算秒/小时）** 衡量云端服务器算力消耗。理解账户配额边界与常见算力陷阱，可以显著降低 `User memory limit exceeded`、超时中断和额度意外耗尽风险。

## 1. 非商用账户月度配额层级与常见默认上限

### 非商用三档月度额度模型（参考基准）
- **Community（社区档）**：每月 **150 EECU-hours**（`540,000` EECU-seconds）；
- **Contributor（贡献者档）**：每月 **1,000 EECU-hours**（`3,600,000` EECU-seconds）；
- **Partner（合作者档）**：每月 **100,000 EECU-hours**（`360,000,000` EECU-seconds）。

> 注意区分两类配额：**“每日 EECU 保护上限”**默认常显示为未配置封顶（Unlimited），用于个人项目每日成本防呆；这**不代表每月非商用总额度无限**。此外，“配额充足”只是权限前提，单个脚本仍可能因内存、聚合体量或请求超时失败。

### 官方公开技术限额参照
| 限额维度 | 默认参考值 | 工程含义 |
| --- | --- | --- |
| 并发交互请求上限 | 每项目 **40**（标准端点 / 高并发端点） | 高并发切片下载需控制线程与退避，遇 HTTP 429 立即降频 |
| 请求速率上限 | **100 次/秒** 或 **6,000 次/分钟** | 避免循环内高频 `getInfo()` 或密集小块拉取触顶 |
| 平均并发批处理任务 | 约 **2** 个（视套餐与队列） | 批量导出队列上限为 **3,000** READY 任务，宜合并导出勿碎片化刷屏 |
| 单次请求负载 / 大聚合响应 | 请求体 **10 MB** / 大型 `reduceRegion` 返回上限 **100 MiB** | 大像元数归约应使用 `Export` 或适当调高 `scale`，勿强行 `getInfo()` |
| 个人资产库存储上限 | **250 GB** / **10,000 个资产** | 及时清理临时中间 Asset |

## 2. 账本观测与隐私红线

- **双源核对**：在 EOStage 中可通过 `gee_quota_status` 查看当前账号识别出的档位与本地估算 EECU 账本状态；若有条件开启了云端配额与监控监控接口，应如实标注结果来自**实时监控读数**还是**官方档位推理 + 本地估算账本**。
- **零凭据泄露**：任何诊断报告中严禁打印 OAuth Token、服务账号私钥文件内容、授权跳转完整网址或带签名查询串的私有链接。
- **严禁多账号规避限制**：主动教唆或自动化切换多账号以绕过 GEE 配额属于违反服务条款的行为，应通过优化计算图、缩小研究区、减少波段、调粗测试尺度或分期导出解决。

## 3. 五个立竿见影的降本排雷习惯

1. **尽早过滤（Filter Early）**：紧跟 `ImageCollection()` 立刻连写 `.filterBounds(roi.bounds())`、`.filterDate(start, end)` 和云量过滤，再 `.select(needed_bands)`，避免无关景和全波段进入后续计算图。
2. **杜绝 `.map()` / Python 循环里的 `getInfo()` 与 `print()`**：每循环调一次即发一次完整网络 RPC 并强制局部求值，是耗时暴涨与 HTTP 429 的头号元凶。
3. **禁用无必要中间 `.clip()` 与大范围强制 `.reproject()`**：强制全区固定投影会阻止 GEE 利用多尺度金字塔缓存；把裁切和投影参数统一放到最终导出或统计调用。
4. **用 `.filter()` + `.limit()` 替代 `.toList()`**：`toList()` 会迫使系统先物化整个集合列表元数据，大集合易瞬间 OOM。
5. **用独立过滤分支或掩膜逻辑替代 `ee.Algorithms.If()`**：`ee.Algorithms.If()` 往往同时构建真假两个计算分支再做选择，计算图复杂度翻倍。
